Fundamento

Automatizar é delegar uma sequência de trabalho a um sistema

Uma automação recebe algum tipo de entrada ou evento, aplica regras e executa ações sem depender de uma pessoa repetindo cada passo.

Algo acontece

Exemplo simples

Exemplo empresarial

Exemplo com IA

Chegou e-mail → IA identifica assunto → fluxo direciona ao setor correto.

👤

⚙

Gatilho

Toda automação precisa saber quando começar

O gatilho é o evento que coloca o fluxo em movimento.

Por evento

Por agenda

Por mudança

Algoritmos dentro da automação

Automação ganha escala quando consegue repetir o mesmo procedimento

Em programação, chamamos isso de repetição ou loop.

PARA CADA cliente na lista verificar_situacao(cliente) SE cliente.tem_pendencia enviar_lembrete(cliente)
Uma regra + uma lista = escala. O que alguém faria 300 vezes manualmente pode ser descrito uma única vez.
Exemplo

Processar uma fila é diferente de tratar apenas um caso

Um registro

“Verifique se Ana está inadimplente.”

Uma coleção

“Para cada cliente, verifique se está inadimplente e execute a ação correspondente.”

A automação transforma a pergunta de “como faço isto?” em “como faço isto para todos?”.

O mundo real

Processos reais têm casos que fogem do caminho principal

Uma automação profissional precisa prever o que acontece quando algo dá errado.

Dado ausente

O cliente não informou telefone.

Sistema indisponível

O serviço externo não respondeu.

Caso fora da regra

Valor extremamente alto exige avaliação especial.

Erro tratado é parte do processo. Erro ignorado vira problema operacional.

Integrações

API é uma forma padronizada de um sistema pedir algo a outro

Pedido

“Sistema de vendas, me informe os dados do pedido 1842.”

Resposta

“Pedido 1842: cliente Ana, valor 320, status Pago.”

GET /pedidos/1842 { "cliente": "Ana", "valor": 320, "status": "Pago" }
Não é necessário decorar código agora. O importante é compreender a função da API como uma “porta de comunicação” entre sistemas.

Ponte para IA

Regras funcionam muito bem quando conseguimos escrever claramente o critério

Regra explícita

SE valor ≥ 500 → pedir aprovação.

Problema difícil de escrever como regra

“Leia esta mensagem e descubra se o cliente está irritado.”

Quando a entrada exige interpretação de padrões, a IA pode ocupar uma etapa do fluxo.
IA dentro do processo

Algumas tarefas são difíceis de expressar com dezenas de IFs

Texto

Classificar, resumir, extrair informação.

Imagem

Reconhecer objetos ou ler documentos.

Previsão

Estimar risco, demanda ou probabilidade.

Geração

Produzir rascunhos de texto ou conteúdo.

A IA fornece uma saída. O restante do fluxo ainda precisa decidir o que fazer com essa saída.
Dois exemplos de IA

“IA” não significa uma única tecnologia

Modelo preditivo / Machine Learning

Recebe dados e produz classificação, pontuação ou previsão. Ex.: chance de cancelamento de um cliente.

IA generativa

Interpreta e produz conteúdo. Ex.: resumir atendimento, redigir resposta, extrair informações de um documento.

Nos dois casos, precisamos de dados, critérios de qualidade e uma forma segura de usar o resultado.

IA generativa

Quando usamos IA generativa, a instrução também vira parte do processo

Instrução vaga

“Resuma o atendimento em até 5 tópicos, destacando problema, ação tomada, pendência e próximo passo. Não invente informações.”

Um prompt de automação deve ser previsível. Contexto, tarefa, formato de saída e limites reduzem ambiguidades.
