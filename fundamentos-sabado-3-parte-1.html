Dado, informação e conhecimento não são a mesma coisa

Em IA: modelos recebem dados, produzem saídas e ajudam pessoas ou sistemas a tomar decisões. O valor aparece quando a saída gera ação útil.
Um mesmo valor, muitos sentidos

Um dado sozinho pode ser ambíguo

“42”

Pode ser idade, quantidade, preço, código de produto, temperatura ou número de chamados.

“Cancelado”

Pode ser um pedido, uma consulta, uma assinatura, uma reserva ou um pagamento.

Para um computador, contexto precisa ser representado.

Por isso bases de dados usam campos, nomes de colunas, tipos e regras. Eles ajudam a explicar o que cada valor significa.

Prática no computador

Transforme valores soltos em informação

Complete no seu computador

Pegue um valor qualquer da sua tarefa inicial e escreva uma frase que dê contexto suficiente para outra pessoa entender o que ele representa.

Dados têm natureza diferente

O tipo do dado limita o que podemos fazer com ele

Número

quantidade, preço, nota, distância

Texto

nome, observação, categoria, endereço

Data/hora

compra, consulta, vencimento, acesso

Verdadeiro/Falso

pago?, ativo?, aprovado?, disponível?

Exemplo: “10” como número permite somar. “10” como texto pode ser apenas parte de um código. Tratar o tipo errado pode gerar erro ou resultado sem sentido.
Prática no computador

Escolha o tipo mais adequado

Preço → número. Inadimplente? → verdadeiro/falso. CPF → texto/identificador, pois não fazemos operações matemáticas com ele. Vencimento → data/hora.

Atenção

Nem todo problema pode ser “corrigido” automaticamente

Erro evidente

Idade = −8. Sabemos que não é válida, mas ainda não sabemos qual é a idade correta.

Dado ausente

Telefone em branco. Podemos detectar a ausência, mas não inventar o número.

Possível duplicidade

“Marcos Lima” e “MARCO LIMA” parecem iguais, mas precisamos de outros identificadores para confirmar.

Análise começa com pergunta

Uma base não “fala” sozinha

Perguntas descritivas

Transição: quando a pergunta pode ser respondida por passos claros, começamos a construir um algoritmo.

Algoritmo vem antes da linguagem de programação.
Computadores são literais

“Faça do jeito certo” não é um passo executável

Ambíguo

“Se o cliente comprar bastante, dê um desconto bom.”

Mais preciso

“Se o valor da compra for maior ou igual a R$ 500, aplicar 10% de desconto.”

Quanto mais repetível e verificável a regra, mais fácil transformá-la em algoritmo e depois em automação.
Prática no computador

Elimine a ambiguidade

Regra vaga: “Clientes antigos recebem prioridade quando estão esperando muito.”

Critérios úteisProcure números, condições observáveis e um resultado claro.
SE tempo_de_cadastro ≥ 2 anos E tempo_de_espera ≥ 15 minutos, ENTÃO marcar atendimento como prioridade. Não é a única resposta possível; o importante é que os critérios possam ser medidos.

Guardando valores

Variável é um nome associado a um valor

idade = 67

“idade” nomeia o valor 67.

valor_compra = 280

O nome explica o que 280 representa.

cliente_ativo = verdadeiro

Também podemos guardar condições lógicas.

nome = "Carla" idade = 67 valor_compra = 280 cliente_ativo = True

Não é necessário decorar sintaxe. Observe como nomes claros tornam o algoritmo legível.

Aguardando execuçãoAltere os valores e teste diferentes casos.

Experimente

Teste pelo menos quatro combinações. Encontre um caso com 0%, um com 5% e um com 10% de desconto.

Mais de uma condição

E e OU mudam completamente a regra

E — todas precisam ser verdadeiras

“Compra ≥ 200 E cliente é membro.” Se uma condição falhar, o conjunto é falso.

OU — basta uma ser verdadeira

“Cliente tem 60+ OU possui prioridade médica.” Basta uma condição ser atendida.

Escrevendo lógica sem depender de linguagem

Pseudocódigo descreve o algoritmo de forma legível

LER valor_compra LER cliente_membro SE valor_compra >= 500 desconto = 10 SENÃO SE valor_compra >= 200 E cliente_membro desconto = 5 SENÃO desconto = 0 MOSTRAR desconto
Por que usar?

Ajuda a organizar o raciocínio antes do código.

  • Foca na lógica
  • É independente de linguagem
  • Facilita revisão
  • Ajuda a encontrar falhas
Prática no computador

Crie um algoritmo de atendimento prioritário

Cenário

Uma clínica oferece prioridade se o paciente tem 60 anos ou mais OU se possui uma condição de prioridade registrada. Caso contrário, entra na fila comum.

Procure 4 elementosentradas, condição, resultado verdadeiro e resultado alternativo.
LER idade
LER possui_prioridade

SE idade >= 60 OU possui_prioridade = verdadeiro
    MOSTRAR “Fila prioritária”
SENÃO
    MOSTRAR “Fila comum”
A lógica permanece

Programação é uma forma de tornar o algoritmo executável

Pseudocódigo

SE idade >= 60 OU prioridade MOSTRAR "Fila prioritária" SENÃO MOSTRAR "Fila comum"

Python

if idade >= 60 or prioridade: print("Fila prioritária") else: print("Fila comum")
Não precisamos memorizar Python aqui. O ponto é perceber que o código é uma tradução formal de uma lógica que já deveria estar clara.

Casos de teste

Não basta funcionar para um exemplo

Caso comum

Valor = 250 numa regra “valor ≥ 200”. Esperamos verdadeiro.

Caso de fronteira

Valor = exatamente 200. O operador ≥ inclui o limite.

Caso inválido

Valor negativo ou campo vazio. O algoritmo precisa decidir como tratar.

Um bom algoritmo precisa ser testável.

Por que este algoritmo está errado?

Teste mentalmente

O que acontece com uma pessoa que tem exatamente 60 anos, se a regra do negócio diz “60 anos ou mais”?

Uma distinção importante

Regra programada e modelo aprendido não são a mesma coisa

Algoritmo baseado em regra

Uma pessoa define explicitamente: “SE valor ≥ 500, desconto = 10%”.

Modelo de IA

O sistema aprende padrões a partir de exemplos para estimar algo: risco, categoria, probabilidade, próxima palavra.

Mas ambos dependem de dados. A diferença está em como a regra de decisão é obtida.
Escolher a ferramenta certa

Nem tudo precisa de Inteligência Artificial

Regra clara e estável

“Vencimento passou e pagamento não ocorreu → enviar lembrete.” Automação tradicional resolve bem.

Muitos padrões difíceis de escrever

“Esta transação parece fraude?” Pode fazer sentido usar aprendizado de máquina.

Linguagem e conteúdo

“Resuma este documento” ou “classifique a intenção da mensagem”. IA generativa pode ajudar.
